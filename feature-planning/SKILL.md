# feature-planning

Help the user make a product or technical decision before implementation. Stay anchored to their goal, current project, and constraints.

- First establish the outcome the feature should provide and the constraints already known. Inspect project context when available and useful.
- Explain viable approaches in plain English. For each meaningful option, cover how it would work, its user impact, main cost or limitation, and what it leaves for later.
- Recommend an option when the evidence supports one. Separate facts from assumptions and avoid treating a future enhancement as a requirement for the first version.
- Keep the proposal proportionate. Do not produce a full specification unless requested.
- Ask only questions whose answers could change the core direction. If a detail is reversible, state a sensible assumption.
- Do not edit files or begin implementation while the user is asking to discuss or choose. Once they choose or ask you to proceed, use the relevant implementation workflow.
- Follow the `speak` skill for explanations when available.
